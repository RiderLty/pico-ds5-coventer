# Pico DS5 Lua 工作台

这是 Pico DS5 的独立单页前端：全屏 Lua 编辑器、WebUSB/Web Serial 连接、设备日志、浏览器脚本库和可选 AI 助手。首次未连接时编辑器为空且只读，AI 和设备操作均不可用；连接后立即读取设备当前运行脚本并替换编辑器，读取完成才允许编辑。断线时保留编辑内容并只读；重连读取设备后，有本地修改则保留并标注差异，无本地修改则更新为设备脚本；浏览器命名脚本库仍可用于保留多个版本。“加载到内存”不会写 Flash，“写入存储”才会把当前运行镜像保存到设备 KV。

## AI 配置与设备连接

AI 的 API 地址、模型、API Key、温度、上下文与任务额度、轮数、流式等参数，统一保存到设备
Flash KV 的 `ai_cfg` 键（JSON UTF-8，最多 4096 字节），与 Lua 脚本分别存储。每次连接都会
重新读取当前设备的配置；读取成功前 AI 不可用，失败时可在设备面板点击“刷新”重试。
保存设置会等待设备确认，失败不会把新配置当作已保存。

旧版本浏览器 `ds5_ai_cfg_v1` 配置仅在设备没有 `ai_cfg` 时迁移，成功写入后才清除旧记录，
已有设备配置优先。API Key 与其他参数一起保存在设备 KV；请求仍由浏览器直连 AI 端点，
导出的 Lua 不包含 AI 参数。需要配套本次新增 AI 配置操作码的固件；旧固件可读脚本，AI
配置读取会报不支持并保持禁用，不会静默改用浏览器配置。

脚本读取、AI 配置读取/保存都绑定当前连接；断开会终止 AI 请求、清除配置缓存与 AI 撤销栈，
编辑器内容在断线期间保留，但禁止编辑；AI 任务不会在重连后自动继续。
旧连接的读取、文件导入或 AI 修改不能应用到新设备。重连时有本地修改则保留，
点击“读取设备”可主动用设备脚本替换。页面首次打开不恢复旧草稿或预制脚本，
断线保留仅限当前页面；关闭或刷新前请将未保存修改导出，页面会提示未保存内容。
需要模板时请连接后显式选择“预制模板 → 编辑器”。

## WinUSB 自动重连

首次点击“连接 USB”并授权后，页面启动、设备重新插入或 USB 热重载时会通过
`navigator.usb.getDevices()` 找回已授权的设备，自动连接并重新读取脚本和 AI 配置。
不会自动弹授权框；换站点、清除权限或使用隐私窗口后，需重新手动授权。
WinUSB 未启用时无法连接；可按 BOOT 或由 Lua 启用。驱动尚未就绪时按退避间隔有限重试，
再次插入或回到页面会重新检查。手动“断开”或选择 UART 会暂停自动连接并记住选择；
再次点击“连接 USB”恢复。

仅匹配 `054c:0ce6` 且有 `0xFF` 厂商类、bulk IN/OUT 的接口；真正的 HID DS5 会被排除。
已记住设备序列号时只连接该设备；未记住序列号且有多个候选时要求手动选择。
新版固件仅在启用 WinUSB 时提供 Pico SDK 缓存的板卡唯一 ID，所有 WinUSB 布局使用同一
序列号，以支持跨拔插的持久授权。旧固件没有 USB 序列号，Chromium 会在拔出时撤销临时
授权，仅前端无法绕过；刷入新版后需手动连接授权一次。

自动重连保留当前页面未提交的编辑内容，不自动执行或保存脚本，也不会继续之前的 AI 任务。

## 开发

```bash
npm install
npm run dev
```

默认地址是 `http://localhost:5173`。设备 API 需要 HTTPS 或 localhost，并要求支持 WebUSB/Web Serial 的 Chromium 浏览器。

设备使用新版预制 Lua 脚本时，不会在 5 秒后自动启用额外接口：该逻辑已整段注释保留，
原作用是延迟开启键盘、鼠标和 WinUSB 并触发重枚举。运行中按下再松开 BOOT 即可仅开启
WinUSB，随后可通过网页连接。自定义 `on_boot_button(pressed)` 可调用 `dev_enable` 选择接口，
并在松开时返回 `true` 拦截默认动作；示例见 [BOOT 用法](../docs/lua-scripts.md#boot-按键与接口启用)。
若希望插上主机即启用接口，在脚本顶层写 `dev_enable(1, 1, 1)`，上传运行并保存到设备后
重新上电。固件先运行启动脚本，再按最终配置首次枚举，无需延时启用或再次断开重连。
运行中上传执行和回调中的接口变更仍走热重载，相同配置不重载。

运行 `npm run build` 后，`dist/` 可直接作为静态站点发布。Vite 使用相对资源路径，支持
GitHub Pages 的仓库子路径，无需额外设置 base。

## GitHub Pages

`.github/workflows/pages.yml` 在推送到 `main` 且前端相关文件有修改时，自动执行
`npm ci`、`npm run build` 并部署 `dist/`。仅修改固件不会触发；前端目录、内置的
`docs/lua-api.md`、`scripts/default.lua`、`tools/pico-device.js` / `.mjs` 和工作流本身
的修改会触发。需要重新部署时，也可在 Actions 中手动运行 Build and Deploy Frontend。

首次使用需在仓库 Settings → Pages 中将 Source 设为 GitHub Actions。私有仓库需
GitHub 套餐支持 Pages；如果设置时提示套餐不支持，需要升级套餐或将仓库设为公开。
发布地址以工作流的 `github-pages` 部署链接为准。
