# DS5 触摸板输出

`pad_touch(x0, y0, x1, y1, down1, down2)` 将两个触点经跨核队列交给 core0，
由 `ds5_pad.c` 写入 Report ID `0x01` 的 63 字节 USB 输入报告 body。
主机线上报告共 64 字节：首字节为 Report ID，两个触点在 body 偏移 32 / 36
（包含 ID 后为 33 / 37），每个触点占 4 字节。

| 触点内偏移 | 内容 |
| --- | --- |
| 0 | bit7=1 表示抬起；bit0..6 为 contact ID |
| 1 | X bit0..7 |
| 2 | 低 4 位为 X bit8..11；高 4 位为 Y bit0..3 |
| 3 | Y bit4..11 |

例如 ID=0、按下、X=`0x123`、Y=`0x234` 对应 `00 23 41 23`。
抬起后对应 `80 23 41 23`。此前错误的输出把 contact 放在末字节，
并将 Y 的高/低位按错误顺序拼接，导致主机把坐标误读为 contact ID、抬起位和其他坐标。

坐标按原生值传递，不做 0..65535 的归一化或比例缩放；DS5 输入侧声明尺寸为 1920×943。
Lua 入口将坐标钳位到 12-bit 的 0..4095，core0 打包再做同样的上限保护，避免超界回绕。
来自其他分辨率触摸板的数据需要脚本自行缩放。

每次新的按下沿分配 7-bit contact ID；同一次触摸移动期间保持稳定，两个在位触点 ID 不同，
计数回绕时跳过另一在位触点的 ID。抬起保留该触点 ID 和最后坐标，仅置 inactive 位，
避免输入快照将无效槽位清零时产生一次原点坐标。`pad_disconnect()` 清除触点并报告抬起。
报文布局已对照仓库现有输入解析器 `lib/hidkit/src/layouts/gamepad_ds5.h` 核对。
输入层没有透传原始 tracking counter，因此同槽位更换手指须有 down→up→down 才能分配新 ID。

验证：

```bash
python3 tools/test_ds5_touch.py
```

测试包含独立字节样本、实际输出报告经现有 hidkit DS5 解析器回读、坐标 nibble 与 bit7
边界、双指、抬起、再次按下、ID 回绕、超界钳位及断连。仍需上板验证主机/游戏的触摸行为。
